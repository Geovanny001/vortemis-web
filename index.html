      [ ENGINE ]

      What it does, what it does not.

      WHAT IT DOES

      Read, score, map, store

      Ingests Zeek conn.log or a live tshark capture, builds a six-feature vector per flow, scores it with an autoencoder, maps anomalies to five MITRE tactics and writes the result to PostgreSQL.

      WHAT IT DOES NOT

      No payloads, no agents

      No packet bodies, no host agents, no inline blocking and no packet storage. Only Layer 3 and 4 metadata leaves the sensor, and the engine only reads what the flow record already contains.

      WHO IT IS FOR

      Teams that already run Zeek

      SOC analysts triaging suspicious flows, network engineers with existing sensor output, and detection engineers who want a versioned contract instead of a black box.

      [ 01 ] PIPELINE

      Four steps, one pass.

      01 INGEST

      Zeek or tshark

      TSV or JSON connection logs, or a live sensor. Byte offsets are persisted, flow ids are deterministic and inserts are conflict-safe.

      02 SCORE

      Six features

      Inter-arrival time, forward and backward bytes, duration, ratio and failed state. The autoencoder reconstructs and the error becomes a probability around the 95th percentile.

      03 MAP

      Five tactics

      Explicit network rules assign a MITRE tactic only to flows above the configured threshold, so every label can be explained.

      04 SERVE

      Store and query

      A PostgreSQL star schema behind a versioned /v1 with filters, keyset pagination and SQL aggregations.

      [ 06 ] FAQ
      
        
      Questions we get.
      
      
      

      
      
        
      
          Does it inspect payloads?
          
      No. Vortemis only reads connection metadata: addresses, ports, bytes, duration, inter-arrival time and connection state.
      
        
      
        
      
          Where does detection run?
          
      On the engine, next to the database. Presentations consume HTTP and never touch the model or PostgreSQL.
      
        
      
        
      
          Is the model calibrated for real traffic?
          
      Not yet. The current checkpoint is a documented baseline; calibration and behavioural features are an open workstream.
      
        
      
        
      
          Can a frontend use it?
          
      Yes. The contract is versioned, documented and shipped as an OpenAPI file with every release.
      
        
      
        
      
          What happens if the log is truncated or rotated?
          
      The ingestion checkpoint detects it and restarts from the beginning. Deterministic flow ids prevent duplicates.
